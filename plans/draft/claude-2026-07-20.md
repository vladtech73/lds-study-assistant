## Goal

A private, offline-capable study assistant over the standard works and the user's
own copies of General Conference talks and Come, Follow Me material, that:

- answers scripture/doctrine/lesson-planning questions **with verse- and talk-level citations**
- never invents a reference (every claim traceable to a retrieved chunk)
- runs entirely on one RTX 5070 Ti 16GB, no cloud calls
- ships as a clean public GitHub repo containing **code only** — no copyrighted text,
  no built indexes, no fine-tuned weights derived from copyrighted material
- is modular enough that swapping the base model or embedding model is a config edit

**v1 is a command-line tool.** No web UI, no server. Scope framing per the evaluation:
this is a *starter design* that must do one thing — grounded, cited scripture Q&A from a
terminal — before anything else is built on it.

Success = `python -m lds_study.cli ask "What does Alma 32 teach about experimenting on the word?"`
returns a grounded answer with `[Alma 32:27]`-style citations that resolve to real
retrieved chunks, on a fresh clone.

Setup time on a clean Windows machine is expected to be roughly half an hour, but that is
an **aspiration for the README, not an acceptance gate** — model pulls and CUDA wheel
installs are network- and machine-bound.

## Constraints

**Legal / ToS — this is the binding constraint, not a footnote.**

- **No blanket "the standard works are public domain" claim.** That statement is too
  coarse to build on, and the earlier draft of this plan overstated it. The correct model
  is *text vs. edition*: the underlying 19th-century texts of the Book of Mormon, KJV Bible,
  D&C, and Pearl of Great Price are generally out of copyright, but **every modern published
  edition carries its own copyrightable apparatus** — versification changes, chapter
  headings, footnotes, cross-reference chains, section introductions, the Topical Guide and
  Bible Dictionary, and post-1920 additions to the D&C (e.g. Official Declaration 2, added
  1978). Those are *not* free to redistribute.
- Therefore: license status is decided **per source entry, not per volume**. Each entry in
  `configs/sources.yaml` records `license`, `license_url`, `verified_on`, and `notes`, and
  the ingest pipeline refuses to run against an entry whose `license` is `unverified`.
  Auto-download is limited to sources whose license has been checked and recorded; headings,
  footnotes, and study aids are **stripped during normalization** rather than indexed, both
  to avoid the edition apparatus and because they pollute retrieval.
- Nothing produced here is an "official" edition, and the repo says so.
- **General Conference talks and Come, Follow Me manuals are © Intellectual Reserve, Inc.**
  The repo must not contain them, must not redistribute them, and must not publish
  embeddings, adapters, or datasets derived from them. Ingest is **bring-your-own-files**:
  the user supplies personal-use downloads (Gospel Library exports, Liahona PDF/ePub)
  into a gitignored `data/raw/user/` directory.
- No scraping of churchofjesuschrist.org by default. If a fetcher is included at all it
  is opt-in, rate-limited, robots.txt-respecting, single-user, and clearly labeled
  "personal use only — you are responsible for compliance."
- Output must carry a standing disclaimer: unofficial, not produced or endorsed by
  The Church of Jesus Christ of Latter-day Saints, not a substitute for scripture,
  prophets, or personal revelation.

**Hardware / platform**

- RTX 5070 Ti = Blackwell, compute capability **sm_120** → needs CUDA 12.8+ and a
  `cu128`-or-newer PyTorch wheel. Pin this in `requirements-cu128.txt` and check it in
  `scripts/check_env.py`. The check **reports tested-vs-untested rather than asserting
  failure**: older wheels may run via PTX JIT or not at all depending on version, so
  `check_env.py` warns with the specific fix command when it sees a non-cu128 build and
  errors only when torch reports zero usable CUDA devices.
- 16GB VRAM budget: generator ~9-10GB, embedder + reranker ~2GB, leaving little headroom
  once context grows. Concretely: `lds_study index` **unloads the generator** before
  embedding and reloads after; `ask` keeps the reranker on CPU if
  `rag.reranker_device: cpu` (the default on a single 16GB card); enable **quantized KV
  cache** (Q8) in the Ollama/llama.cpp options and cap `num_ctx` in `configs/models.yaml`
  rather than inheriting a 128k default that reserves VRAM it will never use.
- Windows 11 + PowerShell + repo `.venv` (per global rules). bitsandbytes/Unsloth on
  Windows is the most fragile dependency — isolate it in an optional extra so RAG users
  never install it. **Document the WSL2 fallback from day one**, not as a later rescue:
  `docs/FINETUNE_WINDOWS.md` covers native attempt → known failure signatures → WSL2 +
  CUDA toolkit path, with the same `train_qlora.py` invocation on both sides.

**Engineering**

- No secrets in code; `.env` at repo root, `.env.example` with placeholders.
- `data/`, `indexes/`, `models/`, `outputs/` all gitignored **except** an explicit
  allowlist of structural files: `data/**/.gitkeep`, `data/README.md`,
  `data/raw/user/EXAMPLE.meta.json`. The CI copyright gate checks staged paths against
  that allowlist rather than rejecting everything under `data/`, which would block the
  scaffold commit itself.
- Package name is **`lds_study`** (`src/lds_study/`). `lds` is too generic to claim on
  PyPI and collides with unrelated packages; the console script stays `lds`.
- Install story: **`pip install -e .` installs the full RAG path** — LlamaIndex, Chroma,
  BGE-M3, rank_bm25 are base dependencies, not an extra. The only extras are
  `[finetune]` (Unsloth/peft/trl/bitsandbytes) and `[dev]` (pytest/ruff). There is no
  `[rag]` extra; the earlier draft contradicted itself on this.
- Tests must pass with no network and no GPU (mock the LLM and embedder).

## Approach

**Primary: RAG first, fine-tuning second — and the fine-tune is for *style*, not *facts*.**

This is the single most important design decision. Scripture study demands exact
quotation and exact reference. A QLoRA fine-tune bakes paraphrased text into weights
and will confidently misquote verses — the worst possible failure mode here. RAG keeps
the authoritative text outside the model, where it can be quoted verbatim and cited.

So:

- **Option A (RAG) is the recommended and default path.** Build it fully.
- **Option B (QLoRA) is scaffolded but scoped narrowly**: teach response *format*
  (citation discipline, lesson-plan structure, tone), trained on instruction pairs whose
  answers are grounded only in sources marked `redistributable: true` with a verified
  license. Never train on conference talks or Come, Follow Me — and, per the evaluation,
  there is **no flag to override this**. The exclusion is unconditional in code.
- **Hybrid = A + a small B adapter applied to the same base model**, so retrieval still
  supplies the facts. This is the end state worth aiming at, but only after A is measurably
  working. Do not start here.

**Retrieval design (the part that determines quality):**

- **Verse-atomic chunking for scripture.** A chunk = one verse, with `book/chapter/verse`
  metadata and neighbor-window expansion at retrieval time (fetch verse ±2 for context).
  Never chunk scripture by character count — it destroys citations.
- **Section chunking for talks/lessons**: split on headings, ~600-900 tokens, keep
  `title/author/date/session/url` metadata; carry paragraph anchors for citation.
- **Hybrid retrieval**: BM25 (exact phrase — critical for "who said 'a marvelous work'")
  + dense vectors, fused with RRF, then a cross-encoder rerank to top-k ~8.
- **Citation enforcement in the answer layer**: the generator is prompted to cite by
  chunk id; a post-step validates every emitted citation against the retrieved set.
  **Unsupported citations are never silently stripped** — stripping leaves prose that
  reads as sourced but is not, which is worse than an obvious failure. Failure semantics
  are specified in step 4.

**Model recommendation.** The 16GB tier moves fast; the plan ships a *shortlist plus a
benchmark harness* rather than betting the repo on one checkpoint. Defaults:

| Role | Default | Why | Alternates |
|---|---|---|---|
| Generator | **Qwen2.5-14B-Instruct, Q4_K_M** (~9GB) as the *interim* default | Known-good, mature Ollama/GGUF/Unsloth packaging today — work can start without waiting on toolchain support. Apache 2.0, solid instruction following, proven QLoRA target at 16GB | Promote **Qwen3-14B** to default once `lds eval` confirms it (packaging/quant support for newer releases often lags); `gpt-oss-20b` (MoE, fast) if throughput matters more than depth; Gemma 3 12B only if vision is wanted — Gemma's Terms of Use restrict derivative distribution and complicate Option B |
| Embeddings | **BGE-M3** (multilingual, 8k ctx, dense+sparse) | robust on archaic English; hybrid-friendly | `nomic-embed-text-v1.5` (light, Ollama-native, good default for low-VRAM runs); `Qwen3-Embedding-0.6B` |
| Reranker | **bge-reranker-v2-m3** | large precision win on verse lookup | `Qwen3-Reranker-0.6B`; or disable rerank via config if VRAM-bound |
| Serving | **Ollama** for the default path | one-command install on Windows, handles download+quantization | llama.cpp for power users. **vLLM is not a supported Windows path** — it is Linux/WSL2 only; do not present it as an easy alternative. Unsloth loads HF weights directly for Option B |

Model download happens *in scripts*, never manually: `scripts/pull_models.py` reads
`config/models.yaml` and shells out to `ollama pull` / `huggingface_hub.snapshot_download`
into a gitignored `models/`. `configs/` is the only place a model id appears.

**Vector store: Chroma, decided.** Persistent local mode, no server, metadata filtering
sufficient for `volume`/`book`/`date_range`. LanceDB is not carried as a parallel option;
revisit only if Chroma's filtered-query performance becomes a measured problem.

**LlamaIndex surface area (rip-out path).** Only four things are used: `TextNode` +
metadata, `ChromaVectorStore`, `VectorIndexRetriever`, and the BM25 retriever. Everything
else — chunking, fusion, reranking, prompting, generation — is our own code in
`src/lds_study/`. All LlamaIndex imports live in `src/lds_study/index/backend_llamaindex.py`
behind a `Retriever` protocol defined in `index/base.py`, so replacing it means writing one
new backend module. No LlamaIndex type crosses into `rag/` or `cli.py`.

**Rejected alternatives:** (1) pure fine-tune, no RAG — misquotation risk, no citations,
re-train needed for every new talk; (2) LangChain as the core framework — heavier
abstraction than needed here, and its retrieval primitives are exactly what we're
customizing.

### 2. Data preparation (`src/lds_study/data/`, `lds prepare`) — PR2

`configs/sources.yaml` is the manifest — one entry per source with `id, type, loader,
path_or_url, license, license_url, verified_on, redistributable: true|false`.
Rules enforced in `data/manifest.py`, not in docs:

- `license: unverified` → the loader refuses to run for that entry, with a message naming
  what to check. New sources are `unverified` until a human fills in `license_url` and
  `verified_on`.
- `redistributable: false` → content may be written only under `data/` (gitignored) and is
  **unconditionally excluded** from any exported dataset. There is no override flag; the
  earlier `--allow-restricted` escape hatch is removed, because a legal boundary with a
  bypass switch is not a boundary.
- Every downloaded artifact records URL + sha256 + retrieval timestamp in
  `data/raw/public/MANIFEST.json`. A re-run with a changed sha256 fails loudly rather than
  silently ingesting different text; `--refresh` accepts the new hash deliberately.

Modules:

- `sources/public_scripture.py` — downloads structured JSON for BoM/D&C/PGP/KJV from a
  license-verified mirror. Normalization **drops chapter headings, footnotes,
  cross-reference chains, and study aids**, keeping verse text only (see Constraints:
  text vs. edition).
- `sources/user_files.py` — walks `data/raw/user/**` and dispatches by extension:
  `.epub`, `.pdf`, `.html`, `.txt`, `.md`. This is how conference talks and Come, Follow Me
  get in. Extracts title/author/date from ePub OPF metadata or PDF outline, falls back to
  a sidecar `.meta.json` the user can write.
- `normalize.py` — unicode NFC, smart-quote and dash normalization, de-hyphenation from
  PDF extraction, footnote-marker stripping, whitespace collapse.
- `chunk_scripture.py` — one `Chunk` per verse: `{id: "bofm/alma/32/27", text, book,
  chapter, verse, volume, canonical_ref: "Alma 32:27"}`.
- `chunk_prose.py` — heading-aware recursive split with overlap, paragraph anchors.
- Output: `data/processed/chunks.jsonl` + a per-source stats report (chunk counts,
  token histogram, dropped/empty records) so silent extraction failures are visible.

**Fixture-driven acceptance tests land in this PR, not later.** `tests/fixtures/` holds
tiny hand-checked public-domain samples — one scripture chapter as raw source JSON, one
small ePub, one small PDF — with expected chunk output committed alongside. Tests assert:
verse count and ids for the chapter; ~20 known verses match reference text character-for-
character; headings/footnotes are absent from chunk text; ePub/PDF metadata extraction
produces the expected title/date; a `redistributable: false` fixture never appears in an
export. These run offline with no GPU and become the regression net for every later PR.

Done when: `lds prepare` on scripture-only produces the expected verse-chunk count per
volume (assert against a committed per-volume count table, not a remembered ~41k),
`lds prepare --stats` shows zero empty chunks, the fixture tests pass, and adding a single
ePub to `data/raw/user/` and re-running adds its sections with correct title/date metadata.

### 3. Index build (`src/lds_study/index/`, `lds index`) — PR3

- Embed with BGE-M3 in batches, fp16, with a progress bar and resumable checkpointing
  (a full scripture embed is ~40k vectors — minutes, but don't lose it on a crash).
- Persist to **Chroma** (persistent client) under `indexes/{profile}/`, gitignored.
- Build a parallel BM25 index over the same chunk ids.
- `HybridRetriever`: dense top-50 ∪ bm25 top-50 → RRF → cross-encoder rerank → top-8,
  then `expand_context()` pulls neighbor verses for scripture hits.
- Filters exposed: `volume`, `book`, `date_range`, `source_type` (so "only scriptures"
  or "only 2024-2026 conference" is a query-time flag).
- **VRAM discipline:** `index` stops the Ollama generator (or waits out `keep_alive`)
  before loading the embedder, and does not hold embedder and reranker resident
  simultaneously. `ask` loads the generator once, keeps the reranker on the device named
  in `rag.reranker_device` (default `cpu`), and logs peak VRAM at `--verbose` so
  contention is visible rather than an OOM surprise.

Done when: `lds index --profile default` completes and a smoke query for a distinctive
phrase returns the correct verse at rank 1 for 10/10 hand-picked phrases, with peak VRAM
logged below 15GB.

### 4. RAG answer layer (`src/lds_study/rag/`, `lds ask`) — PR3

- Static system prompt in `prompts/study_assistant.md`; retrieved chunks go in a
  **user/tool role**, never spliced into the system prompt.
- Prompt contract: answer only from context; cite as `[[chunk_id]]`; say "I don't find
  this in the indexed sources" rather than guessing; distinguish scripture text from
  a speaker's commentary from the assistant's own synthesis.
- `citations.py` — parse emitted `[[id]]` markers, verify each against that call's
  retrieved set, render to human refs (`Alma 32:27`,
  `Nelson, "Think Celestial," Oct 2023`).

**Citation failure semantics (explicit — no silent stripping).** Given
`invalid` = markers not in the retrieved set, and `coverage` = fraction of substantive
claim-bearing paragraphs carrying ≥1 valid marker, `lds ask` takes exactly one of four
paths, all configurable in `configs/rag.yaml` and all surfaced in the exit code and JSON
output:

| Condition | Behavior |
|---|---|
| `invalid == 0` and `coverage ≥ citation.min_coverage` (default 0.8) | Answer returned, `status: ok` |
| `invalid > 0` **or** `coverage < min_coverage`, first attempt | **Regenerate once** at temperature 0 with a corrective instruction naming the offending markers and the valid id list |
| Still failing after the retry | **Refuse**: return the retrieval results as a plain source list with no synthesized prose, `status: unsupported`, exit code 2 |
| Retrieval returned nothing above `retrieval.min_score` | **Refuse before generating**, `status: no_evidence`, exit code 3 |

An invalid marker is never removed to make the surrounding sentence look clean. When
`--strict` is set, the retry is skipped and any invalid marker refuses immediately.
`--show-context` prints the retrieved chunks so any answer is auditable by hand.
All four paths are unit-tested against a mocked generator.

- Task modes for v1 (thin prompt variants, same pipeline): **`study` (default), `lesson`
  (Come, Follow Me outline with discussion questions), `talk` (talk prep)**. The `music`
  /hymn mode is **deferred** — it needs a legally-clear hymn corpus that does not yet
  exist in this design, and it is scope creep until `study` is measurably good. It is
  named in Out of scope with the corpus question recorded in the Decisions appendix.
- **No `serve` command in v1.** FastAPI + SPA is deferred to a post-v1 PR (step 9).

Done when: `lds ask` returns answers where every rendered citation resolves; a
deliberately out-of-corpus question ("what did the prophet say last Tuesday") hits the
`no_evidence` or `unsupported` path with the documented exit code rather than a
fabrication; and a forced-bad-citation test proves the regenerate-then-refuse ladder.

### 5. Evaluation harness (`src/lds_study/eval/`) — PR4, before Option B

`eval/golden.yaml`: ~50 questions in four buckets — verse lookup by phrase, doctrinal
synthesis, lesson planning, and adversarial/out-of-corpus. Metrics: retrieval recall@k
(does the gold chunk appear), citation validity rate, **refusal rate on adversarial items**,
and a manual 1-5 quality column. `lds eval --profile X` writes `outputs/eval/{date}.md`.

Golden questions reference only public-domain scripture so the file itself is committable;
questions over restricted sources live in a gitignored `eval/golden.local.yaml`.

This is what makes the model shortlist decidable instead of vibes: run the same eval
against Qwen2.5-14B (interim default), Qwen3-14B, and gpt-oss-20b and pick from the table.
Whichever wins becomes the documented default in `configs/models.yaml`.

Done when: a comparison table for ≥2 generator models exists in `outputs/eval/`, and the
thresholds it establishes (citation validity, adversarial refusal rate) are written into
`configs/rag.yaml` as the regression baseline steps 6-7 must not degrade.

### 6. Option B — QLoRA scaffold (`src/lds_study/finetune/`) — PR5, optional extra

- `pyproject` extra `[finetune]`: unsloth, peft, trl, bitsandbytes, datasets. Documented
  as "not needed for RAG." Install notes and the **WSL2 fallback** live in
  `docs/FINETUNE_WINDOWS.md` (written in this PR): native Windows attempt first, the
  known bitsandbytes/Triton failure signatures on sm_120, then the WSL2 + CUDA 12.8 path
  running the identical `train_qlora.py` command.
- `build_dataset.py` — generates instruction pairs from sources that are
  `redistributable: true` **and** license-verified. The filter is unconditional: records
  from restricted sources are dropped with a counted warning, and **no flag re-enables
  them**. A unit test asserts that a restricted fixture cannot reach `sft.jsonl`.
  Pair types: cross-reference reasoning, "explain this verse with citation", lesson-outline
  formatting. Output `data/processed/sft.jsonl` in ShareGPT/chat format.
- `train_qlora.py` — Unsloth, 4-bit base, LoRA r=16/α=32 on attn+MLP, grad checkpointing,
  bsz 1 + accum 8, seq 2048, ~2-3 epochs. Fits 16GB for a 14B base; note in the docstring
  that dropping to 7-8B is the fallback if OOM.
- `merge_and_export.py` — merge adapter, export GGUF, register with Ollama so the hybrid
  path (step 7) uses one serving stack.
- README section: **adapters trained on restricted material must not be published.**

Done when: training runs to completion on a tiny debug slice (`--max-steps 20`) and the
resulting adapter loads.

### 7. Hybrid wiring — PR5

`configs/models.yaml` gains `generator.adapter: null | path`. When set, `lds ask` uses the
adapted model with the identical retrieval pipeline. Re-run `lds eval` and keep the adapter
**only if citation validity and adversarial refusal rate meet or beat the PR4 baseline** —
a style gain that costs groundedness is a regression, not a tradeoff. Document that result
honestly in the README either way, including "we tried it and reverted" if that is the
outcome.

### 8. Repo hygiene, model card, disclaimers — spread across PRs

- `README.md`: disclaimer block at the very top; quickstart; hardware notes; "what this
  repo does and does not contain."
- `MODEL_CARD.md` template: intended use, out-of-scope use (not doctrinal authority, not
  for producing content presented as official), base model + license, training data
  provenance, known limitations (archaic-English retrieval, hallucinated attribution risk),
  eval results, contact.
- `.github/`: issue templates, a PR checklist item "contains no copyrighted text",
  and a CI workflow running lint + tests on CPU with no network.
- Pre-commit hook **and** CI running `scripts/check_staged_data.py`: fails if any staged
  path under `data/`, `indexes/`, or `models/` is outside the structural allowlist
  (`data/**/.gitkeep`, `data/README.md`, `data/raw/user/EXAMPLE.meta.json`). Path-based,
  not grep-based — a grep for keywords is trivially bypassed by a PDF or a rename.

### 9. Post-v1 — local web UI (deferred)

Only after step 5 shows `study` mode meeting its thresholds. `serve`: minimal FastAPI +
single-page UI, localhost bind by default, all model output escaped before DOM insertion,
no external CDN assets, same citation-failure semantics surfaced in the UI.

### 10. Post-v1 — music/choir support (deferred)

Blocked on a legally-clear hymn corpus: 1985 hymnal arrangements and the 2024+ *Hymns—For
Home and Church* releases are © Intellectual Reserve; many underlying texts and tunes are
public domain but the published arrangements are not. Resolve the corpus question
(Decisions appendix) before designing this. A defensible v1 of this feature is
*topic→hymn-number lookup* over public-domain first-line/topic data, with no lyric text
indexed at all.

## Risks

- **Misquotation / false attribution** — the core product risk. Mitigated by verse-atomic
  chunks, verbatim quoting from context, and programmatic citation validation. Residual:
  the model can still paraphrase a talk and attribute it to the wrong speaker; the eval
  harness's adversarial bucket exists to measure this.
- **Copyright drift** — someone (including a future me) commits a conference talk or
  publishes an adapter trained on one. Mitigated by gitignore + path-based CI staged-file
  check + the `redistributable` flag enforced in code with no override. Residual: the
  allowlist itself is a soft spot — a mistaken allowlist entry re-opens the hole, so
  changes to `check_staged_data.py` and `.gitignore` warrant explicit review.
- **Edition-vs-text copyright nuance** — the riskiest legal ambiguity is not the verse
  text but the apparatus around it (headings, footnotes, modern D&C additions) and
  whichever mirror we pull from having quietly copied a modern edition. Mitigated by
  stripping apparatus in normalization, per-source `license_url` + `verified_on`, and
  refusing `unverified` sources. Residual: mirror provenance is only as good as its own
  claims — documented as a known limitation in `docs/LEGAL.md` rather than papered over.
- **Blackwell toolchain** — bitsandbytes/Unsloth/flash-attn on sm_120 + Windows is the
  likeliest hard blocker. Contained by making `[finetune]` optional; fallback is WSL2.
- **VRAM contention** — generator + embedder + reranker plus context growth can OOM on
  16GB. Mitigated by explicit load/unload around index builds, CPU reranking by default,
  quantized KV cache, a capped `num_ctx`, and configurable `keep_alive`.
- **Source quality** — mirrors vary in versification and typos. Mitigated by the sha256
  manifest, the committed per-volume chunk-count table, and a spot-check test against ~20
  known verses.
- **Model shortlist staleness** — this tier turns over every few months. Mitigated by
  keeping model ids in `configs/models.yaml`, starting from a known-good interim default
  rather than the newest release, and letting `lds eval` decide promotions.
- **Scope regrowth** — the deferred `serve` UI and `music` mode are the likeliest things to
  creep back in early. Mitigated by making them steps 9-10 behind an explicit quality gate.

## Out of scope

- Any redistribution of Church-copyrighted text, or a hosted/multi-user deployment.
- Scraping churchofjesuschrist.org or Gospel Library as a default code path.
- **v1 only:** the `serve` web UI (step 9) and `music`/hymn mode (step 10) — deferred, not
  cancelled, and gated on `study` mode meeting its eval thresholds.
- Non-English corpora, audio/video transcription, mobile apps.
- Pretraining or full fine-tuning; only QLoRA adapters are considered.
- Any claim of doctrinal authority or official status.
