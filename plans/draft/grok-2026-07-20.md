# Local LDS Study Assistant — Repo Scaffold, RAG + QLoRA Starter

*Author: grok · 2026-07-20*

## Goal

Stand up a private, local-first GitHub repo for an LDS scripture/study assistant that runs on an **RTX 5070 Ti 16GB**. Success means:

- A clear modular repo layout with env setup, docs, and legal disclaimers.
- Recommended open model(s) that fit 16GB for both **RAG inference** and **QLoRA fine-tuning**.
- Starter scripts for: (1) data prep of BoM / KJV / D&C / PoGP / Conference / Come Follow Me into citable chunks + optional instruction pairs; (2) Option A RAG (LlamaIndex); (3) Option B QLoRA (Unsloth); (4) a documented hybrid path.
- Every answer path prioritizes **source citations**, gospel-study alignment, and **non-official / personal-use** framing.

This plan covers **structure + starter design only** — not shipping production UI or training a final adapter.

## Constraints

- **Hardware:** single RTX 5070 Ti **16GB VRAM**, Windows-friendly (PowerShell + Python 3.11+). Leave ~2–4GB headroom for embeddings + KV cache during RAG.
- **Private / local:** no cloud LLM dependency for core chat; Hugging Face downloads allowed for weights/data tooling.
- **Accuracy > cleverness:** prefer retrieval + citations over memorized “gospel answers.”
- **Copyright / ethics:**
  - Treat General Conference talks and Come Follow Me as **Church-copyrighted**; personal study use only; **do not redistribute** full talk corpora in the public repo.
  - Scripture texts: use clearly licensed public sources (e.g. public-domain KJV; Church-published scripture only where terms allow personal use). Prefer user-local data dirs that stay gitignored.
  - Never claim Church endorsement or “official” status.
- **No secrets in git:** `.env` for paths/tokens; sample `.env.example` only.
- **Modular:** data / rag / train / serve packages can run independently.
- **Do not implement in this planning phase** (dual-plan Phase A).

## Approach

**Primary recommendation: Hybrid — RAG-first, light QLoRA second.**

| Layer | Role | Why |
| --- | --- | --- |
| **RAG (default)** | Retrieve verse/talk/lesson chunks → answer with citations | Best accuracy, auditable sources, updates without retrain |
| **QLoRA (optional)** | Tone, lesson-outline format, choir/music helper style, citation habit | Improves format/alignment; must not replace retrieval for factual claims |
| **System prompt + guardrails** | Study framing, refuse speculative doctrine as authority | Alignment without over-fine-tuning |

**Rejected as primary:** full-parameter fine-tune (VRAM/time); RAG-only with no format adapter (weaker lesson/choir UX); fine-tune-only on scriptures (hallucination + stale corpus risk).

### Model recommendations (16GB)

**Default inference (RAG):** `Qwen/Qwen2.5-14B-Instruct` via **Ollama** or **llama.cpp/vLLM** at **Q4_K_M / AWQ 4-bit** (~9–11GB). Strong instruction following + long context for multi-passage study. Leaves room for embedding model + retrieval.

**QLoRA training base:** same family — `Qwen/Qwen2.5-14B-Instruct` with **Unsloth 4-bit QLoRA** (r=16–32, seq 2048–4096, batch 1 + grad accum). Fits 16GB with gradient checkpointing.

**Lighter fallback:** `meta-llama/Llama-3.1-8B-Instruct` (or 3.2 8B) if VRAM/context pressure is high, or for faster iteration.

**Embeddings:** `nomic-ai/nomic-embed-text-v1.5` or `BAAI/bge-small-en-v1.5` (CPU or small GPU slice). Store vectors in **Chroma** (simple local) or **Qdrant** (if scaling later).

**Optional reasoning boost (tight fit):** try a stronger 14B/24B quant only after RAG pipeline is stable; do not start with models that consume >14GB at target context.

### Library choices

| Concern | Choice | Rationale |
| --- | --- | --- |
| RAG | **LlamaIndex** (+ optional LangChain later) | Fast local RAG, citation metadata, simple vector store adapters |
| Train | **Unsloth** + PEFT/TRL | Best 16GB QLoRA DX on Windows/Linux; Axolotl as optional YAML path later |
| Serve | CLI first (`python -m lds_assistant.chat`), Gradio optional | Minimal surface; cite sources in stdout/UI |
| Config | `pyproject.toml` + `configs/*.yaml` | One place for model IDs, chunk sizes, paths |

### 4. Data preparation pipeline (starter script design)

**Entry:** `scripts/01_prepare_data.py` → calls `src/lds_assistant/data/*`.

**Sources (user-local, documented in `sources.md`):**

| Corpus | Suggested ingest | Chunk unit | Metadata |
| --- | --- | --- | --- |
| Book of Mormon | user-provided plain/JSON/OSIS | verse or small verse groups | book, chapter, verse, url/ref |
| KJV Bible | public-domain dump | verse | book, chapter, verse |
| D&C | user-provided | section + verse | section, verse |
| Pearl of Great Price | user-provided | verse / chapter | book, chapter, verse |
| General Conference | **local only** HTML/PDF user export | paragraph (~256–512 tokens) | speaker, title, date, session, url |
| Come Follow Me | **local only** | section / activity block | manual, week, lesson title, url |

**Pipeline steps:**

1. `download.py` — only for **explicitly allowed** public sources (e.g. KJV); for Church materials, print instructions + expected folder layout under `data/raw/{corpus}/`.
2. `clean.py` — normalize whitespace, strip nav chrome, preserve verse numbers.
3. `chunk.py` — emit JSONL: `{id, text, source, citation, metadata}`.
4. `instruct_pairs.py` — optional SFT pairs from chunks: “Explain {ref}”, “Outline a 10-min lesson on {theme} using these passages”, “Suggest choir warm-ups thematically linked to {ref}” — **always include gold citations in the target**.

**Chunking defaults (`configs/chunking.yaml`):** scriptures ≈ 1–4 verses; talks ≈ 300–500 tokens, overlap 40–60; store canonical citation string for UI.

**Done when:** running prepare on a tiny fixture corpus produces JSONL + schema validation in tests.

### 5. Option A — RAG pipeline (LlamaIndex)

**Entry:** `scripts/02_build_index.py`, `scripts/03_chat_rag.py`.

**Design:**

- Load processed JSONL as LlamaIndex `Document`s with metadata.
- Embed with configured embed model; persist Chroma at `indexes/chroma/`.
- Query engine: top-k 4–8, MMR optional; response synthesizer uses `prompts.py` study system prompt.
- **Every answer** must list citations (`book chapter:verse` or talk title + paragraph id).
- LLM backend: OpenAI-compatible local endpoint (Ollama / llama.cpp server) pointing at Qwen2.5-14B; fallback HuggingFace local if needed.

**Done when:** CLI question returns answer + citation list from fixture index without GPU OOM at default settings.

### 6. Option B — QLoRA fine-tuning (Unsloth)

**Entry:** `scripts/04_train_qlora.py` → `src/lds_assistant/train/qlora_unsloth.py`.

**Design:**

- Load base via Unsloth `FastLanguageModel.from_pretrained(..., load_in_4bit=True)`.
- LoRA on attention + MLP projections; `r=16`, `lora_alpha=32`, dropout 0–0.05.
- Dataset: `data/instruct/*.jsonl` chat format; max seq 2048 (4096 if VRAM allows).
- Trainer: TRL `SFTTrainer`, `paged_adamw_8bit`, grad checkpointing, batch 1, accum 8–16.
- Save adapter to `adapters/lds-qwen14b-lora/`; do **not** commit weights.
- Eval: holdout instruct pairs + “citation present” heuristic.

**Axolotl:** optional `configs/axolotl_lds.yml` stub only — Unsloth is the supported 16GB path in v1.

**Done when:** dry-run train on 20 samples completes 1 step on 16GB (or documents skip if no GPU in CI).

### 7. Hybrid wiring

**Order of operations for users:**

1. Prepare data → build RAG index → chat with RAG (ship this first).
2. Optionally build instruct pairs → QLoRA → serve RAG with `llm = base + adapter` **or** Ollama base + note that adapters need Transformers/Unsloth serve path.
3. Inference policy in `prompts.py` / `query.py`:
   - Factual scripture/talk questions → **must retrieve**; model may only synthesize.
   - Lesson outline / choir helper → retrieve theme passages, then apply format style (adapter helps).
   - If retrieval empty → refuse confident doctrine; ask clarifying question.

**Done when:** `docs/ARCHITECTURE.md` diagrams RAG-first + optional adapter; README “Quick start” has Hybrid as recommended.

## Risks

- **Copyright takedown / ToS:** publishing talk corpora or marketing as official — mitigate with gitignore + LEGAL + no redistributed dumps.
- **Hallucinations on doctrine:** mitigate with mandatory retrieval for factual modes; system prompt humility.
- **VRAM surprise (5070 Ti + Windows overhead):** mitigate with 8B fallback config and smaller context.
- **Unsloth/Windows CUDA quirks:** document WSL2 as supported path if native Windows wheels fail.
- **Source drift:** Church site HTML changes break scrapers — prefer user-exported files + documented layout over brittle scrapers.
- **Fine-tune overconfidence:** adapters may sound authoritative while wrong — keep RAG authoritative for facts.
